# AI School OS — Android app (Google Play)

The Play Store app is the live portal, **https://ai-schoolportal.mejortechworld.com**, wrapped in a
**Trusted Web Activity (TWA)**: Chrome opens the site full screen with no address bar. There is no
separate app code — every deploy of the website updates the app at once. A new Play release is only
needed to change the app's name, icon, colours, package settings or Android version support.

| Setting | Value |
|---|---|
| Package name (application ID) | `com.mejortechworld.aischool` — **permanent**: it can never change after the first upload |
| Site | `ai-schoolportal.mejortechworld.com`, start URL `/` |
| App name / launcher name | AI School OS / AI School |
| Colours | status bar, navigation bar and splash `#0B1330` (the web manifest's theme colour) |
| Icons | taken from the live site's `/icons/icon-512.png`, `maskable-512.png`, `badge-96.png` (notification icon) |
| Notifications | on — web push is delegated to Android notifications (Android 13+ asks the user) |
| Fallback | Custom Tabs (if the phone's browser can't run a TWA) |
| Orientation | default (follows the phone) |
| Play Billing | **off** (fees are paid through Paystack on the website, as today) |
| Min Android | 7.0 (API 24 — required by androidbrowserhelper 2.7); target API 36 (Bubblewrap 1.27 default) |

Files here:

- `twa-manifest.json` — the single source of truth. Bubblewrap generates the Gradle project from it.
- `app/`, `build.gradle`, `gradle/`, `gradlew*`, `settings.gradle`, `gradle.properties` — the generated
  Android project (regenerated by `bubblewrap update`; don't hand-edit — change `twa-manifest.json`).
- `store_icon.png` — the 512×512 icon for the Play listing.

Build outputs (`*.aab`, `*.apk`, `app/build/`) and signing keys (`*.jks`, `*.keystore`) are in
`.gitignore` and must never be committed.

  sign uploads with this upload key. If the upload key is ever lost or leaked, the Play Console account owner

## Digital Asset Links (full screen, no address bar)

Android only hides Chrome's address bar if the site publishes
`https://ai-schoolportal.mejortechworld.com/.well-known/assetlinks.json` listing the app's package name and
**every** certificate that signs it. The deploy writes and uploads that file from two GitHub repository
**variables** (not secrets — fingerprints are public):

GitHub → the repository → *Settings → Secrets and variables → Actions → Variables* → **New repository variable**

| Name | Value |
|---|---|
| `ANDROID_PACKAGE_NAME` | `com.mejortechworld.aischool` |
| `ANDROID_SHA256_FINGERPRINTS` | comma-separated SHA-256 fingerprints: the upload key above **and**, after the first upload, Play's *App signing key certificate* SHA-256 (Play Console → *Test and release → App integrity → App signing*) |

Then re-run the deploy (*Actions → Deploy → Run workflow*). The deploy's last step reports
`Android app links: 200 application/json…`. Check it yourself:

```
curl -i https://ai-schoolportal.mejortechworld.com/.well-known/assetlinks.json
```

and with Google's checker:
`https://digitalassetlinks.googleapis.com/v1/statements:list?source.web.site=https://ai-schoolportal.mejortechworld.com&relation=delegate_permission/common.handle_all_urls`

How it's served: `infrastructure/deploy/assetlinks.mjs` writes `apps/web/dist/.well-known/assetlinks.json`
during the deploy; the SFTP step uploads it separately (the main mirror skips `.well-known/` so cPanel's SSL
validation files are never deleted); Apache serves it as a real file, as `application/json`
(`apps/web/public/.htaccess`). With the variables unset nothing is written and the deploy behaves as before.

**Symptom of a wrong or missing fingerprint:** the app opens with a thin browser address bar at the top.
Fix the variable, redeploy, then clear the app's storage (or reinstall) on the test phone.

## Building

Prerequisites (once):

1. Node.js 18+ and `npm i -g @bubblewrap/cli` (or run it with `npx @bubblewrap/cli`).
2. On first run Bubblewrap offers to download **JDK 17** and the **Android SDK** into `~/.bubblewrap/`
   (about 1 GB). Accept — or point it at existing ones in `~/.bubblewrap/config.json`:
   ```json
   { "jdkPath": "C:/path/to/jdk-17", "androidSdkPath": "C:/path/to/android-sdk-with-tools-or-bin-folder" }
   ```
   Bubblewrap checks for JDK **17** when it asks; Android Studio's bundled JDK 21 also builds this project
   (Gradle 8.11 / AGP 8.9) when written into the config file directly. **The JDK path must not contain
   spaces** — Bubblewrap's signing step breaks on `C:\Program Files\…` ("'C:\Program' is not recognized").
   Use Bubblewrap's own download, or copy the JDK to e.g. `C:\jdk17`.

If `bubblewrap build` fails at the signing step on your machine, sign the Gradle outputs by hand (passwords
come from environment variables, so they never appear on the command line or in logs):

```
set KSPW=<keystore password>
gradlew.bat assembleRelease bundleRelease
zipalign -f -p 4 app\build\outputs\apk\release\app-release-unsigned.apk app-release-unsigned-aligned.apk
java -jar <sdk>\build-tools\36.1.0\lib\apksigner.jar sign --ks C:\Users\user\ai-school-android-keys\upload-keystore.jks --ks-key-alias upload --ks-pass env:KSPW --key-pass env:KSPW --out app-release-signed.apk app-release-unsigned-aligned.apk
copy app\build\outputs\bundle\release\app-release.aab app-release-bundle.aab
jarsigner -sigalg SHA256withRSA -digestalg SHA-256 -keystore C:\Users\user\ai-school-android-keys\upload-keystore.jks -storepass:env KSPW -keypass:env KSPW app-release-bundle.aab upload
```

(Bubblewrap itself prints the passwords in its error message if signing fails — delete such logs.)

Build (from this folder):

```
cd android
bubblewrap build
```

It asks for the keystore and key passwords (from `upload-keystore-password.txt`); to avoid the prompts set
`BUBBLEWRAP_KEYSTORE_PASSWORD` and `BUBBLEWRAP_KEY_PASSWORD` in that terminal only. Outputs:

- `app-release-bundle.aab` — **upload this to Play**;
- `app-release-signed.apk` — install on a test phone: `adb install app-release-signed.apk`.

Dependency download note: Bubblewrap's template lists only `google()` and `jcenter()` as repositories.
JCenter is retired and was unreachable when this project was first built, so the committed `build.gradle`
also lists `mavenCentral()`. `bubblewrap update` rewrites `build.gradle` — after an update, check that both
`repositories { … }` blocks still contain `mavenCentral()` (add it above `jcenter()` if not).

Windows note: if the build fails with *"'gradlew.bat' is not recognized"*, the environment variable
`NoDefaultCurrentDirectoryInExePath` is set in that terminal; clear it (`set NoDefaultCurrentDirectoryInExePath=`
in cmd, or `Remove-Item Env:NoDefaultCurrentDirectoryInExePath` in PowerShell) and build again.

## Versioning: releasing an update

Every upload to Play needs a **higher `versionCode`** (a whole number Play uses) and a readable
`versionName` (shown to users).

```
cd android
bubblewrap update --appVersionName=1.0.1     # bumps appVersionCode by 1 and regenerates the project
bubblewrap build
```

or edit `twa-manifest.json` by hand (`"appVersionCode": 2`, `"appVersion": "1.0.1"`), then
`bubblewrap update --skipVersionUpgrade` and `bubblewrap build`. Commit `twa-manifest.json` and the
regenerated project; upload the new `.aab` to the same Play track.

You only need a new release for app-shell changes (name, icons, colours, notification setting, shortcuts,
target API — Google raises the required target API level each year, usually by 31 August; run
`npm i -g @bubblewrap/cli@latest` and `bubblewrap update` to pick up the new default). Website changes reach
the app on the next launch, with no Play release.

## Behaviour inside the app (web side)

- `apps/web/src/pwa/android-app.ts` detects the TWA (`document.referrer` is `android-app://…` on launch,
  remembered for the session). Inside the app the "Install the app" card and menu item never show.
- WhatsApp (`wa.me`, `api.whatsapp.com`) and YouTube links open the installed app via an Android intent,
  falling back to the web page. `tel:` and `mailto:` go to the dialler / email app as in Chrome. Paystack
  checkout opens over the app with a small address bar and returns to the portal after payment.
- Schools' own website domains are not part of the app (different site); they open in a Custom Tab.
