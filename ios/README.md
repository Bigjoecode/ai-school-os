# AI School OS — iPhone and iPad app (App Store)

The App Store app is the live portal, **https://ai-schoolportal.mejortechworld.com**, inside a native iOS shell
built with **Capacitor 8**. Like the Android app (`android/`), there is no separate app code: every deploy of the
website updates the app at once. A new App Store build is only needed to change the shell — name, icon, launch
screen, permissions text, native plugins, or to keep up with Apple's yearly Xcode/SDK requirement.

What the shell adds on top of the website (Apple rejects plain website wrappers — guideline 4.2):

| Native feature | How |
|---|---|
| Push notifications (APNs) | `@capacitor/push-notifications`; the portal sends the device token to `POST /api/push/native`; the API sends through APNs with a .p8 key (`APNS_*` env, see `DEPLOYMENT.md`). Tapping a notification opens the page it's about. |
| Share sheet | `@capacitor/share` — `nativeShare()` in `apps/web/src/pwa/ios-app.ts`; today used by the Share buttons on the For-schools pages, ready for any portal page that adds sharing |
| Haptics | `@capacitor/haptics` — the learning games tap the haptic engine (when game sound is on) |
| Status bar | `@capacitor/status-bar` — follows the portal's light/dark theme |
| Launch screen + offline page | `@capacitor/splash-screen`; `www/offline.html` shows when the portal can't be reached on first launch, and reconnects by itself |
| Offline copy and offline exams | the portal's own service worker, enabled in WKWebView by **App-Bound Domains** (below) |
| Camera, microphone, photos | the portal's own file pickers / voice recorder; the permission texts are in `Info.plist` |

| Setting | Value |
|---|---|
| Bundle ID | `com.mejortechworld.aischool` (same as Android) — **permanent** once uploaded |
| Name on the home screen | AI School OS |
| Loads | `server.url` = `https://ai-schoolportal.mejortechworld.com` (`capacitor.config.json`) |
| Min iOS | 15.0; iPhone and iPad |
| Version | `MARKETING_VERSION` 1.0.0 in the project; CI sets it from `package.json` / the tag / the run input, and the build number from the run number |
| Colours | launch screen and web view background `#0B1330` |

## Files

- `package.json`, `package-lock.json` — the Capacitor CLI, iOS platform and plugins (exact versions). Not part of
  the root npm workspaces: install here with `npm ci`.
- `capacitor.config.json` — **the source of truth** for the shell (URL, allowed navigation, plugins).
- `www/` — the bundled pages: `offline.html` (shown when the portal can't load) and `index.html` (redirects to the
  portal; Capacitor requires one).
- `native/` — the Xcode project (`native/App/App.xcodeproj`), generated by `npx cap add ios` and then edited:
  - `App/Info.plist` — App-Bound Domains, usage descriptions, `ITSAppUsesNonExemptEncryption = false`, arm64;
  - `App/App.entitlements` — Push Notifications (`aps-environment`; CI switches it to `production`);
  - `App/AppDelegate.swift` — hands the APNs token to the push plugin;
  - `App/Assets.xcassets` — app icon (1024×1024, no transparency) and launch image (2732×2732), made from
    `apps/web/public/icons/icon.svg`.
  - `App/CapApp-SPM/Package.swift` — Swift Package Manager list of plugins, rewritten by `cap sync`.
  - Not committed (see `native/.gitignore`): `App/App/public`, `App/App/capacitor.config.json`, `config.xml`,
    build output.

Swift Package Manager is used (no CocoaPods), so `npx cap add ios` / `npx cap sync ios` run on Windows too and
produce a complete project; only compiling and signing need a Mac — done on GitHub Actions (`.github/workflows/ios.yml`).

## After changing the shell

```
cd ios
npm ci
npx cap sync ios        # copies www/ and the config into native/, updates the plugin list
```

Commit `capacitor.config.json`, `www/` and `native/` changes, then run the workflow (below). To add a plugin:
`npm i -E @capacitor/<plugin>@<major matching @capacitor/core>`, then `npx cap sync ios`.

## Building and uploading (GitHub Actions)

*Actions → "iOS app (TestFlight)" → Run workflow* (optionally type the version, e.g. `1.0.1`), or push a tag
`ios-v1.0.1`. The job (macOS runner, newest stable Xcode) installs, syncs, archives with manual signing, exports
an `.ipa` and uploads it to App Store Connect; the build appears in TestFlight after Apple's processing
(usually 5–30 minutes). The `.ipa` and build log are kept as a run artifact for 14 days. The secrets it needs and
how to create them are in **`docs/app-store/README.md`**.

Every upload needs a higher build number for the same version; the workflow uses `<run number>.<attempt>`, which
always goes up. Raise the version (e.g. 1.0.1) for each release you submit for review.

On a Mac you can also open `native/App/App.xcodeproj` in Xcode after `npm ci && npx cap sync ios`, pick your team
under *Signing & Capabilities* (automatic signing) and run it on a phone. Those builds use the APNs **sandbox**:
to test push with them set `APNS_ENV=sandbox` on a test API (TestFlight/App Store builds use `production`).

## How the shell behaves (and its limits)

- **Which pages stay inside the app.** Only `ai-schoolportal.mejortechworld.com` (and the bundled offline page).
  Anything else opens outside the app: Paystack checkout opens in Safari (so school-fee payments complete there;
  the payment is confirmed by Paystack's webhook and shows in the app when the page is opened
  again), WhatsApp and YouTube links open their apps (universal links), `tel:` and `mailto:` open the dialler and
  Mail.
- **Schools' own website domains are not part of the app** (same as Android). They can't be: App-Bound Domains are
  limited to 10, fixed at build time, and with `limitsNavigationsToAppBoundDomains` on, WKWebView refuses to load
  any other site. A school's custom domain therefore opens in Safari. Portal pages for a school (`/s/<slug>`) are on
  the portal domain and work in the app.
- **App-Bound Domains and the service worker.** WKWebView only runs service workers for an app that lists
  `WKAppBoundDomains` in `Info.plist` and turns on `limitsNavigationsToAppBoundDomains`; both are set. The domains
  are the portal, `localhost` (Capacitor's own pages) and `www.youtube-nocookie.com` (lesson video embeds). With
  the service worker, the app keeps the portal's offline copy, and offline exam packs (IndexedDB + WebCrypto, both
  available in WKWebView over HTTPS) open without a connection — **after** the app has once been opened online and
  the exam downloaded, exactly as on the web. **Test this on a real iPhone** (TestFlight): sign in, open the
  offline exams page, download an exam, switch on Airplane Mode, force-quit and reopen the app. If the offline copy
  doesn't appear, the service worker isn't running: check `navigator.serviceWorker.controller` in Safari's Web
  Inspector (Develop menu → the iPhone → AI School OS; release builds are inspectable only if
  `ios.webContentsDebuggingEnabled` is set to true temporarily).
- **iPhone detection in the portal.** The shell adds `AISchoolOS-iOS/1` to the user agent and injects
  `window.Capacitor`; `apps/web/src/pwa/ios-app.ts` detects that, never offers "Install the app", and hides
  digital purchases (see `docs/app-store/README.md`, *Payments*). It calls the native plugins through Capacitor's
  injected bridge, so the website bundle needs no Capacitor package.
- **Web push vs native push.** iOS only allows web push for sites added to the Home Screen, never inside an app's
  WKWebView, so the app uses APNs. Devices are stored in the same `push_subscriptions` table as browsers (endpoint
  `apns:<token>`), so every existing notification path reaches iPhones too. Without the `APNS_*` keys on the
  server, the app simply doesn't offer notifications.
- **Sign-out on a shared phone.** As with browser push, the device stays linked to the last person who turned
  notifications on until someone else signs in on it (then it is re-linked) or they turn notifications off.

## Icon and launch image

Made from `apps/web/public/icons/icon.svg`: the app icon is the mark on a full-bleed square (iOS rounds the
corners; Apple rejects icons with transparency, so it is saved without an alpha channel), the launch image is the
mark centred on `#0B1330`. To change them, replace `native/App/App/Assets.xcassets/AppIcon.appiconset/AppIcon-512@2x.png`
(1024×1024, RGB) and the three identical `Splash.imageset/splash-2732x2732*.png` (2732×2732, mark kept in the
central ~1000 px because the image is scaled to fill).
